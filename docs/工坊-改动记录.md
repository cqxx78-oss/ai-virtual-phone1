# 工坊 · 改动记录

> 本文档用于记录小手机仓库中由「工坊」发起的每一次改动。

## 必读规范与核心指引（必须遵守）

> ⚠️ **重要开发红线**：
> 1. **返回键与导航栈**：凡是涉及**返回键（手机物理返回键、PWA 侧滑手势、屏幕左上角虚拟 `<` 返回按钮）**的逻辑修改、新页面/新弹层接入或故障排查，**必须先完整阅读 `docs/返回键与导航栈规范.md`**！严禁私自使用 `window.history.pushState`、`popstate` 监听或临时标志位，所有页面与模态框必须统一使用 `lib/navigation-stack.ts` 的 `pushNav` / `popNav` 中央调度器。

## 文档要求（必须遵守）

1. **每次改动**（无论是否完成、是否最终生效）都要在本文件中追加一条记录，写明：
   - **要实现什么**：用户提出的需求、期望效果；
   - **改了哪里**：涉及的文件路径、改动的具体位置/逻辑；
   - **验证结果**：是否按预期生效，用户实测反馈；
   - **最终结论**：已实现 / 未实现 / 部分实现 / 已回退 / 暂缓保留，以及后续待办。
2. 涉及多条提交的改动，应列出提交号（SHA 前缀即可），便于追溯和回退。
3. 记录要**如实**，不掩盖未实现或未生效的部分；未生效的原因分析也要写清楚。
4. 文档随改动一起提交进仓库（docs/ 目录），不单独延迟。

### 2025-02-27 · PWA 安装后支持物理返回键进行应用内层级返回

- **状态**：已实现（已提交至 main 分支）
- **要实现什么**：用户反馈在将网页作为 PWA 安装到手机本地后，期望能使用系统自带的物理返回键/侧滑手势，实现应用内层级返回（如：从聊天室返回聊天列表，从任意 APP 返回虚拟桌面），而不是直接退出整个 PWA。
- **改动内容**：

### 2026-08-27 · 购物 APP 详情返回后保持滚动位置

- **状态**：暂缓保留（改动已提交，未确认生效，用户要求保留，后续再做）
- **涉及提交**（按时间顺序，均在 main 分支）：
  - `98e4d49` fix(shopping): 返回列表时恢复滚动位置，避免加购后回到顶部
  - `f8c35c6` fix(shopping): 列表重新挂载时用 ref 回调立即恢复滚动位置，加强详情返回场景
  - `0df5f8e` fix(shopping): 列表层改为始终渲染、详情打开时仅隐藏，彻底解决返回后滚动位置丢失
  - `c300e6e` fix(shopping): 列表层永久常驻显示，详情/订单以浮层覆盖，从根源杜绝返回后滚动位置丢失

#### 要实现什么

用户反馈：购物界面中，**把商品加入购物车后，滚动条会重置到最上方**，每次都要重新滑动，很麻烦。希望加购后（以及打开商品/订单详情再返回后）保持滚动位置。用户原话还提到"很多地方都需要这个功能，一个一个来"，本记录先只覆盖购物 APP。

#### 改动内容（只改了 1 个文件）

**文件**：`components/shopping/shopping-app.tsx`（购物 APP 组件，宿主内置）

逐条：

| 提交 | 改了什么 |
| --- | --- |
| `98e4d49` | ① 新增 `shoppingScrollPosRef`，按 tab（home/orders/cart/account）分别记忆滚动位置；② 滚动容器 `.cp-shopping-scroll` 加 `onScroll` 实时记录 `scrollTop`；③ 新增 `useLayoutEffect`：从商品详情/订单详情返回列表时，把该 tab 上次的位置写回；④ 切换底部 tab 时仍重置到顶部（保留原习惯） |
| `f8c35c6` | 在滚动容器的 `ref` 回调里立即恢复滚动位置（比 effect 更早），作为双保险 |
| `0df5f8e` | 把列表层改为"始终渲染、详情打开时仅 `display:none` 隐藏"，试图从卸载问题改为显隐问题 |
| `c300e6e` | 列表层彻底常驻：`display` 恒为 `contents`，永不隐藏；商品详情/订单详情本就是 `position:absolute; z-index:20` 浮层，天然盖在列表上方，返回时列表树原样未动 |

#### 验证结果（用户实测）

- **首页商品点加购后保持滚动条**：✅ 一直正常（此行为本就存在——加购只改数据、列表未卸载；上述改动也未破坏它）。
- **首页点开商品详情再退出**：❌ 仍回到最上方。
- **订单界面点开订单详情再退出**：❌ 仍回到最上方。
- **购物车界面点开商品再退出**：❌ 仍回到最上方。

三版方案（恢复式、显隐式、常驻浮层式）用户均反馈不生效。最后一版 `c300e6e` 在代码层面已做到列表从不卸载、不隐藏、不被改动 `scrollTop`，理论上不存在丢位置的路径，但用户实测仍未生效。

#### 原因分析（未证实，待后续排查）

最可能的原因：**测试环境没有跑到最新代码**。可能的环节：
1. 自部署站点（Netlify/Vercel/本地）未重新构建/重启；
2. 浏览器缓存了旧的 JS 包（需要硬刷新 `Ctrl+Shift+R` / `Cmd+Shift+R`）；
3. 用户实际运行的购物界面可能并非本仓库的 `components/shopping/shopping-app.tsx`（例如站点由别处构建、或走了不同入口）。

#### 最终结论与后续待办

- **已实现**：无新增功能（首页加购保持滚动为原有行为）。
- **未实现**：详情返回后保持滚动位置（用户已放弃本次继续，暂缓）。
- **待办**（下次继续时按此顺序）：
  1. 确认测试站点/本地环境已部署到 `c300e6e` 并硬刷新；
  2. 若仍不生效，先核实实际运行的购物界面是否来自本仓库该组件（可看页面元素/构建产物）；
  3. 定位到真实运行版本后再决定：继续修，或回退；
- **回退方法**：`git revert 98e4d49 f8c35c6 0df5f8e c300e6e`（按顺序 revert，或一次性 revert 到 `98e4d49^` 之前）。改动只涉及 `components/shopping/shopping-app.tsx`，不影响其他任何功能。
- **保留原因**：改动与购物 APP 原有功能等价（加购/结算/搜索/订单/黑市/代付逻辑未动），无副作用，可安全留在仓库里。
