# AI 虚拟手机 · 物理/虚拟返回键与导航栈规范

> **注意**：如果未来需要修改、新增或适配任何页面的**返回键（物理返回键、手机侧滑手势、屏幕左上角虚拟返回按钮）**逻辑，请**必须先完整阅读本文档**，严格遵循本文档的单一中央调度架构，切勿私自使用 `window.history.pushState` 或 `window.addEventListener('popstate')`！

---

## 1. 核心架构：单一中央导航栈 (`lib/navigation-stack.ts`)

本项目在移动端/PWA 容器下，采用**严格的单向中央导航栈模型**。
所有层级（应用、子页面、模态弹窗、详情页）全部由 `lib/navigation-stack.ts` 集中管理。

### 核心工作原理：
1. **入栈 (`pushNav`)**：
   - 当用户打开一个应用、进入子页面或弹出一个独占全屏/半屏的浮层时，调用 `pushNav(onPop, tag)`。
   - `pushNav` 会向浏览器真实历史栈压入一个状态条目（`history.pushState`），同时在 JS 内存栈中记录对应的 `onPop` 回调。
   - `pushNav` 会返回一个 cleanup 函数（销毁回调），在 React 的 `useEffect` 中直接 `return` 即可。
2. **物理返回键 / 侧滑手势**：
   - 浏览器历史栈出栈 1 帧，触发全局唯一的 `popstate` 监听器。
   - 全局监听器从 JS 内存栈顶弹出一个条目，并执行它的 `onPop()` 回调（例如：关闭子页面、退出聊天室、关闭应用）。
3. **虚拟返回按钮（屏幕左上角 `<` 按钮）**：
   - 虚拟返回按钮**统一直接调用 `popNav()`**，它会触发 `window.history.back()`，从而让虚拟按钮与物理返回键**走完全相同的 `popstate -> onPop` 分发通道**，彻底杜绝 UI 按钮与物理按键逻辑不一致或连跳两级的问题。
4. **桌面底层防误触守卫 (Root Guard)**：
   - 在小手机桌面（栈为空）时，调度器会维持一个底层守卫条目。
   - 用户在桌面上按返回键时，不会直接退出 PWA，而是触发 `registerDesktopExitHandler` 注册的回调，在 `DesktopShell` 中弹出「退出小手机？」确认对话框。

## 2. 如何为新页面 / 新弹层接入返回键

### 模式 A：由状态控制的子页面 / 模态弹层（最常用）
在对应的 React 组件内使用 `useEffect` 监听状态，状态变为开启时调用 `pushNav`：

```tsx
import { useEffect } from "react";
import { pushNav } from "@/lib/navigation-stack";

// 示例 1：商品详情页
useEffect(() => {
  if (selectedProduct) {
    return pushNav(() => {
      setSelectedProduct(null);
    }, `shopping:product:${selectedProduct.id}`);
  }
}, [selectedProduct]);

// 示例 2：设置子页面
useEffect(() => {
  if (currentPage !== "main") {
    return pushNav(() => {
      setCurrentPage("main");
    }, `settings:${currentPage}`);
  }
}, [currentPage]);
```

### 模式 B：全屏挂载型应用 / 独立页面组件
在组件首次挂载时直接入栈：

```tsx
import { useEffect } from "react";
import { pushNav } from "@/lib/navigation-stack";

export function MyFullScreenModal({ onClose }: { onClose: () => void }) {
  useEffect(() => {
    return pushNav(() => {
      onClose();
    }, "myApp:modal");
  }, [onClose]);

  // ...
}
```

### 模式 C：屏幕左上角虚拟返回按钮的编写规范
如果该页面有虚拟返回键，**请直接绑定 `popNav`**（或调用会导致上述状态置空的回调）：

```tsx
import { popNav } from "@/lib/navigation-stack";

<button className="page-back-btn" type="button" onClick={popNav} aria-label="返回">
  <ChevronLeft size={24} />
</button>
```

## 3. 严禁踩雷的禁忌事项（红线）

1. ❌ **严禁在具体组件内私自使用 `window.history.pushState` 或 `window.history.replaceState`**：
   这会破坏中央导航栈的深度计数，导致物理返回键穿透退出应用。
2. ❌ **严禁在具体组件内私自监听 `window.addEventListener('popstate')`**：
   全局只能有 `lib/navigation-stack.ts` 一个 `popstate` 监听器，否则会产生事件竞争与重复回退。
3. ❌ **严禁使用旧的 `window.__phoneBackHandler` 方案**：
   该方案已被中央导航栈彻底取代并废弃。
4. ❌ **不要在 `pushNav` 的 `onPop` 回调里再次调用 `popNav()` 或 `history.back()`**：
   `onPop` 执行时浏览器本身已经完成了退栈，只需修改对应的 React state 即可。

## 4. 已接入导航栈的核心文件清单

- `lib/navigation-stack.ts`：中央调度器
- `components/desktop-shell.tsx`：桌面层应用进出调度 & 退出 PWA 确认弹窗
- `components/chat/phone-chat-app.tsx`：聊天室、联系人面板
- `components/chat/chat-room.tsx`：聊天信息设置页、输入模态框、音视频通话
- `components/chat/chat-settings-panel.tsx`：搜索记录、角色电脑、CSS 编辑器、状态栏定制、聊天特效
- `components/music/music-app.tsx`：每日推荐、歌单详情
- `components/music/music-player.tsx`：全屏音乐播放器、播放队列、歌手页（含下滑退出手势）
- `components/shopping/shopping-app.tsx`：商品详情、订单详情、黑市、搜索、结算弹窗
- `components/diary/diary-entries-app.tsx`：角色日记本、单篇日记、定时/字体/写作面板
- `components/phone-settings-app.tsx`：API/语音/预设/世界书/正则等全部子设置页
- `components/phone-resources-app.tsx`：记忆库、漫卷、记忆详情、记忆设置
- `components/phone-character-app.tsx`：角色详情页、编辑档案页
- `components/phone-theme-app.tsx`：主题色、壁纸、图标、组件、文字、CSS 等全部子面板
- `components/calendar-app.tsx`：日程详情、生理期设置、主题/天数面板
- `components/reality-bridge-app.tsx`：规则编辑、快捷指令向导、数据项编辑
